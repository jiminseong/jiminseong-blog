# 차이 보고 — 14·15·16 재촬영 (DNS 레코드 방식)

촬영일 2026-09-13 / 대상 도메인 `jiminseong.com`
형식: **샷 번호 / 설명에 적힌 것 / 실제 화면**

---

## 특별히 물어보신 두 가지

### 1) DNS 관리에 들어가는 실제 경로

**왼쪽 사이드바가 맞습니다. 다만 클릭하면 같은 창이 아니라 또 다른 사이트로 새 창이 열립니다.**

실제 경로는 창이 **세 번** 바뀝니다.

1. `my.gabia.com` — My가비아 > 서비스 관리 > (종류: 도메인) > 해당 행 `관리`
2. → 새 창 `domains.gabia.com` — 여기 왼쪽 사이드바에 `DNS 관리` 가 있습니다 **(14.png)**
3. → `DNS 관리` 클릭 시 또 새 창 `dns.gabia.com` 으로 이동
   - 여기서 도메인 목록이 나오고, 대상 도메인 행의 `설정` 을 눌러야
   - `dns.gabia.com/dns/internals/total_set` — DNS 레코드 목록 화면 **(15.png)**

즉 "왼쪽 사이드바의 DNS 관리"는 **도착지가 아니라 통로**입니다.
본문에 "새 창이 두 번 열린다"고 미리 알려주지 않으면 독자가 창을 잃어버립니다.

지름길도 있습니다.
- My가비아 서비스 관리 상단의 `DNS관리툴` 버튼을 누르면 2단계를 건너뛰고 바로 `dns.gabia.com` 으로 갑니다.
- 주소를 직접 쳐도 됩니다: `dns.gabia.com`

### 2) 레코드 편집 화면의 칸 이름

가비아가 쓰는 실제 칸 이름은 이렇습니다.

| 일반적으로 부르는 이름 | 가비아 화면의 실제 이름 |
|---|---|
| 타입 / Type | **타입** (드롭다운) |
| 호스트 / Name | **호스트** |
| 값 / Value | **값/위치** |
| TTL | **TTL** (드롭다운, 600/1800/3600 등 고정 선택) |
| 우선순위 | **우선순위** (MX용, A 레코드는 비어 있음) |

- "이름"이 아니라 **호스트**, "위치"가 아니라 **값/위치** 입니다. (둘을 슬래시로 붙여 씁니다)
- 호스트 칸 아래에 `.jiminseong.com` 이 회색으로 붙어 나옵니다.
  즉 `@` 만 넣으면 `jiminseong.com` 이 된다는 뜻입니다. 이 부분을 본문에서 짚어주면 좋습니다.
- 값 칸의 placeholder 는 `IP 주소` 입니다.
- TTL 은 자유 입력이 아니라 드롭다운 선택입니다.

## 샷별 차이

### 14 / "왼쪽 사이드바의 DNS 관리 메뉴" / 위치는 맞지만, 누르면 새 창으로 빠집니다
- 사이드바 구성: 대시보드 / 도메인 관리(전체 도메인, 삭제 도메인) / **DNS 관리** / 예약 도메인
- 강조는 사이드바의 `DNS 관리` 에 넣었습니다.

### 14 / "같은 화면 오른쪽의 네임서버 영역이 함께 보여도 괜찮다" / 네임서버는 **같은 화면에 안 보입니다**
- 네임서버는 오른쪽 영역이 아니라 `네임서버/DNS호스트/DNSSEC` 이라는 **별도 탭** 안에 들어 있습니다.
- 규칙 3("네임서버 항목은 열지도 마")에 따라 그 탭은 누르지 않았습니다.
- 대신 14.png 에는 그 **탭 버튼 자체**가 화면 가운데에 보입니다.
  (`도메인 정보` / `소유자·관리자 정보` / `네임서버/DNS호스트/DNSSEC`)
  독자에게 "이 탭은 오늘 쓰지 않는다"고 짚어주기엔 오히려 이 상태가 낫습니다.

### 15 / "① 대상 도메인 행 또는 설정 버튼 ② 레코드 추가 버튼" / 이 둘은 **서로 다른 화면**에 있습니다
실제로는 단계가 세 겹입니다.

| 단계 | 화면 | 그 화면에 있는 버튼 |
|---|---|---|
| 1 | dns.gabia.com 도메인 목록 | `설정` |
| 2 | DNS 관리 (레코드 목록) — **15.png** | `레코드 수정` |
| 3 | DNS 레코드 수정 레이어 — **16.png** | `+ 레코드 추가` / `저장` / `취소` |

- 15.png 는 2단계(레코드 목록)로 찍었고, ① 도메인 이름 ② `레코드 수정` 버튼을 강조했습니다.
- `레코드 추가` 는 2단계에 없습니다. `레코드 수정` 을 눌러 레이어를 연 뒤에야 나옵니다.
  16.png 안에 `+ 레코드 추가` 버튼이 같이 찍혀 있으니 본문에서 그걸 가리키시면 됩니다.
- **권고**: 본문 순서를 "설정 → 레코드 수정 → (레코드 추가 또는 기존 행 수정) → 저장" 으로 쓰셔야 맞습니다.

### 16 / "저장 버튼" 하나 / 확인이 **두 단계**입니다
- 행 오른쪽에 `확인` / `취소` 가 있고, 레이어 아래쪽에 `저장` / `취소` 가 따로 있습니다.
- 행의 `확인` 은 그 줄을 확정하는 것뿐이고, 서버에 반영되는 건 아래 `저장` 입니다.
- 16.png 는 요청하신 대로 ④ 를 아래쪽 `저장` 에 넣었고, 행의 `확인` 버튼도 화면에 같이 보입니다.
- **권고**: "행의 확인을 누른 다음, 아래 저장까지 눌러야 반영된다" 를 본문에 꼭 적어주세요.
  여기서 저장을 안 눌러 반영이 안 되는 사고가 흔합니다.

### 16 / "추가 폼 또는 기존 A 레코드의 편집 상태" / **기존 A 레코드 편집 상태**로 찍었습니다
- 안전한 쪽을 택했습니다. 기존 A 레코드 행의 `수정` 을 눌러 입력 상태로만 만들고,
  **값은 하나도 건드리지 않았습니다.**
- 화면에 보이는 값은 지금 실제로 들어 있는 값 그대로입니다: 타입 `A` / 호스트 `@` / 값 `76.76.21.21` / TTL `1800`

---

## 값 관련 — 해결됨 (2차 재촬영)

1차 촬영본은 기존 A 레코드를 편집 상태로 열었기 때문에 화면에 `76.76.21.21` 이 떠 있어서,
11.png 의 Vercel 권장값 `216.198.79.1` 과 어긋났습니다. 아래처럼 다시 찍었습니다.

- `+ 레코드 추가` 를 눌러 **새 빈 줄**을 만들고, 거기에만 `A` / `@` / `216.198.79.1` 을 입력했습니다.
- 기존 세 줄(A, CNAME, TXT)은 클릭도 하지 않았고 화면에 그대로 남아 있습니다.
  "다른 줄은 지우지 않는다" 경고의 근거로 그대로 쓰실 수 있습니다.
- 새 줄의 TTL 기본값은 `600` 입니다. (기존 A 레코드는 1800)
- 호스트 칸에 `@` 를 넣으면 바로 아래에 회색으로 `.jiminseong.com` 이 붙어 보입니다.
  독자가 "@ 가 루트 도메인"임을 눈으로 확인하는 부분입니다.

**참고**: 기존 A 레코드의 `76.76.21.21` 은 그대로 남겨뒀습니다.
Vercel 안내가 "레거시 레코드도 계속 동작한다"고 명시하고 있어 당장 바꿀 필요는 없습니다.

## TXT 토큰 마스킹 (2차 재촬영)

- `15.png` · `16.png` 둘 다 TXT 레코드의 `google-site-verification=...` **값만** 단색 박스로 덮었습니다.
- TXT 줄 자체는 남겨뒀습니다. 타입 `TXT` · 호스트 `@` · TTL `600` 은 그대로 보입니다.
- A 레코드와 CNAME 레코드 값은 가리지 않았습니다.

## 규격·마스킹 참고

- 1440 x 900 / 라이트 모드 / 배율 100% — 충족했습니다.
- 크롭 없음(전체 창). 이번 3장엔 '확대' 지정이 없었습니다.
- 마스킹: 우측 상단 `지민성님` 을 단색 박스로 덮었습니다.
- 다른 도메인: `dns.gabia.com` 첫 화면에는 보유 도메인 9개가 전부 나오는데,
  검색창에 대상 도메인을 넣어 1건만 남긴 뒤 다음 단계로 넘어갔습니다.
  그래서 15·16 에는 다른 도메인이 한 개도 없습니다.
- TXT 토큰은 2차 작업에서 가렸습니다. 위 "TXT 토큰 마스킹" 항목 참고.

## 안 건드린 것 확인

- **저장·적용·확인 버튼 누르지 않음.** 행의 `확인` 도, 레이어의 `저장` 도 누르지 않았습니다.
- **기존 레코드 수정·삭제 없음.** 입력칸에 타이핑도 하지 않았습니다.
- **네임서버 항목 열지 않음.** `네임서버/DNS호스트/DNSSEC` 탭은 클릭하지 않았습니다.
- **취소로 닫음.** 레이어 하단 `취소` 로 닫았고, 레이어가 사라진 것을 확인했습니다.
- **닫은 뒤 재조회 결과 (증거)**
  ```
  레코드 개수 : 3개   최근 업데이트 : 2026-02-15 01:10:33   네임서버 : ns.gabia.co.kr
  A      @     76.76.21.21                                                    1800
  CNAME  www   cname.vercel-dns.com.                                           600
  TXT    @     "google-site-verification=0cMzwt-RNI5qEwPrBtmgijVX9CxXFgP0aYN1230rinU"  600
  ```
  촬영 전과 동일하고, **최근 업데이트 시각이 2026-02-15 그대로**입니다.
  저장이 한 번이라도 됐다면 이 시각이 오늘로 바뀌었을 겁니다.
- 가비아 로그인은 카카오 간편 로그인으로 다시 해뒀습니다. 지금 로그인 상태입니다.

### 2차 재촬영(16.png 재촬영 + TXT 마스킹) 후 재확인

- `+ 레코드 추가` 로 생긴 새 줄에만 입력했고, 기존 세 줄은 클릭도 하지 않았습니다.
- 행의 `확인` 도, 레이어의 `저장` 도 누르지 않았습니다. `취소` 로 닫았습니다.
- 닫은 뒤 재조회 결과 (증거)
  ```
  레코드 개수 : 3개   최근 업데이트 : 2026-02-15 01:10:33   네임서버 : ns.gabia.co.kr
  A      @     76.76.21.21                                                    1800
  CNAME  www   cname.vercel-dns.com.                                           600
  TXT    @     "google-site-verification=..."                                  600
  ```
  레코드 3개 그대로, **최근 업데이트 시각도 2026-02-15 그대로** 입니다.
- `https://www.jiminseong.com/` HTTP 응답 **200** 확인했습니다. 사이트 정상입니다.
