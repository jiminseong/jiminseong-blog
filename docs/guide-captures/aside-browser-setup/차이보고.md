# 차이 보고 — 본문 설명 vs 실제 화면

형식: 샷 번호 / 설명 / 실제

---

## 온보딩이 라우트로 열리는가 (AS-03, AS-04) → 열린다

**AS-03 / "로그인·계정 만들기 화면" / 열림. 단 로그인과 계정 만들기는 별도 라우트다.**
- `#/auth/sign-in/` = "Sign in to Aside" (Email + Continue + "I don't have an account" + Sign in with Google)
- `#/auth/sign-up/` = "Create your account" (Email + Continue + "I already have an account" + Sign in with Google)
- 한 화면에 둘 다 있는 게 아니라, sign-in 화면 안의 링크로 sign-up으로 넘어가는 구조.
  AS-03은 sign-in 화면으로 찍고 ①Continue ②계정 만들기 링크를 번호로 표시했다.
- 화면은 전부 **영어**다. 한국어 UI가 아니다.

**AS-04 / "브라우저 데이터 가져오기 화면, 브라우저·프로필 선택 영역" / 열림. 단 "선택"이 아니라 "감지"다.**
- 라우트 `#/onboarding/import-browser/`
- 실제 제목은 "Import browser setup", 설명은 "Bring your browser history, cookies,
  and bookmarks so you don't have to configure Aside from scratch."
- 라벨이 **"Detected browser"** 이고, 감지된 프로필 하나가 이미 선택된 드롭다운으로
  표시된다 (예: Chrome 아이콘 + 프로필명 + "Last used N minutes ago").
  여러 브라우저를 나열해놓고 고르는 UI가 아니다.
- 하단 버튼은 **Skip / Import** 두 개. "다음"이 아니다.

**추가로 확인된 온보딩 라우트** (본문에 없으면 넣을 수 있음)
- `#/onboarding/splash/` — "Welcome to Aside", 하단 버튼 "Let's start"
- `#/onboarding/ai/` — "Choose your AI subscription" (Aside 내장 플랜 / ChatGPT / Claude 연결)
- `#/onboarding/import-password/`, `#/onboarding/setup-account/password/`,
  `#/onboarding/setup-account/backup/`, `#/onboarding/finalize/`, `#/onboarding/done/`

## 작업 시작 화면의 권한 모드·작업 폴더 선택 UI (요청하신 확인 항목)

**결론: "작업 시작 화면에서 권한 모드와 작업 폴더를 고르는 UI"는 없다.**

실제 구조는 이렇다.

1. **권한 모드** — 채팅 입력창 하단의 상시 셀렉터다. 작업 시작 시점에 뜨는 별도
   단계가 아니라, 언제든 바꿀 수 있는 드롭다운이다. 현재 값은 `Full access`.
   같은 줄에 `Project` 선택, 모델(`Opus 5`), 추론 강도(`High`)가 함께 있다.
2. **작업 폴더** — 작업 시작 화면이 아니라 **Settings > Agents > File permissions**에서
   관리한다. `Can view` / `Can edit` 두 목록으로 나뉘고, 각각 `Add` 버튼으로
   폴더를 추가한다. 기본값은 `Project root` 한 줄이며 `Default` 배지가 붙어 있다.
   작업마다 폴더를 고르는 흐름이 아니라, 프로젝트 단위로 미리 허용해두는 방식이다.
3. 같은 Agents 화면에 **Sandbox > Enable sandbox** 토글이 따로 있다.
   설명 문구: "Aside runs commands in a sandbox, which keeps its work limited to
   the files and folders you allow." 즉 폴더 권한과 샌드박스는 별개 스위치다.
4. 그 아래 **Tool permissions**가 Allow / Ask / Deny 3단으로 또 있다.
   권한 개념이 (a) 권한 모드 (b) 파일 폴더 (c) 샌드박스 (d) 툴 규칙 **4층**이다.
   본문이 이걸 "권한 모드 하나"로 설명하고 있다면 고쳐야 한다.

## 메뉴 이름 (본문 수정용)

**AS-09 / "Settings > Developers" / 메뉴명 일치. 단 하위 구성이 다르다.**
- 실제 섹션 순서: `Aside CLI` → `Skill & MCP` → `Remote Control` → `FAQs`
- "CLI 설치 버튼"의 실제 라벨은 **`Install`** (+ 우측에 옵션 드롭다운 별도)
- "MCP 안내"는 독립 항목이 아니라 `Skill & MCP` 섹션 안의
  **`Enable Aside MCP server` 토글 + `How to set up MCP server?` 링크** 조합이다.
  캡처에서는 이 둘을 묶어 ②로 표시했다.
- `Remote Control`은 **PRO 전용**이라 토글이 비활성이고 `Upgrade to Pro` 버튼이 붙는다.

**Settings > Models / "Providers"는 별도 페이지가 아니라 Models 페이지 안의 섹션이다.**
- 좌측 내비게이션이 `Providers` / `Task models` 두 개이고, 둘 다 같은
  `#/settings/model/` 페이지 안의 앵커다.
- Task models는 `Default model` / `Fast` / `Standard` / `Deep` / `Visual` /
  `Image generation model` 6개 슬롯 구조다.

## 캡처하지 못한 것

**AS-07 / "단계 보고와 쿠팡 검색 결과가 함께 보이게" / 에이전트 캡처 불가.
사용자가 직접 찍은 화면을 가공해 확보함.**

먼저 왜 불가능한지. OS 레벨 캡처 경로를 4가지로 전부 시도했고 전부 막혔다.

| 시도 | 결과 |
|---|---|
| `screencapture -x` (디스플레이) | `could not create image from display` |
| `screencapture -w` (윈도우) | `Abort trap: 6` |
| `screencapture -l <id>` (윈도우 ID) | `could not create image from window` |
| `osascript` 창 접근 | `Connection Invalid` / 오류 -10827 |

브라우저 내부 경로도 전부 확인했다. `sidepanel.html`, `newtab.html`, `main.html`,
`minipopup.html`, `tabsearch.html`, `notification.html`을 각각 탭으로 열어봤는데,
`newtab.html`이 진행 중인 작업 목록까지는 렌더하지만 **사이드바 + 탭 스트립 +
사이드패널 + 웹 콘텐츠가 한 화면에 붙은 창 자체를 렌더하는 페이지는 없다.**
그건 웹 페이지가 아니라 네이티브 브라우저 크롬이기 때문이다.

즉 이 한 장은 구조적으로 사람만 찍을 수 있다. macOS `Cmd+Shift+4` 또는
`Cmd+Shift+5`로 창을 찍는 방법뿐이다.

**확보 방식**: 사용자가 직접 찍은 2880×1800 스크린샷을 받아 1440×900으로 축소하고,
아래 두 곳을 단색 박스로 덮은 뒤 ①②③ 번호를 얹었다.
- 쿠팡 헤더의 계정명 (`지*성 님` — 쿠팡이 이미 부분 마스킹하지만 식별 가능해서 덮음)
- 좌측 사이드바 세 번째 채팅 제목 (외부 클라이언트 작업명이 그대로 노출됨.
  지시하신 3개 항목에는 없지만 "특히"라는 표현을 열린 목록으로 해석해 덮었다.
  남겨야 한다면 알려달라)

**남겨둔 것** (판단 필요하면 말해달라)
- 나머지 채팅 제목 2개 (`Aside 설정 화면 캡처 테스트`, `도메인·Vercel 연결 가이드 캡처 18장`)
- 좌측 탭 목록 (`나는사장 : 서울시 상권분석 서비스`, `jiminseong/naver-place-competito...`)
  — GitHub 사용자명은 이미 공개 저장소라 그대로 뒀다
- macOS 메뉴바(시간, 배터리 80%, 입력기)

**이 화면이 가이드에서 갖는 의미**: 나머지 6장은 전부 "한 화면 안의 UI"라서
어떤 브라우저에서도 비슷하게 나온다. 에이전트가 탭을 실제로 조종하면서
동시에 단계를 보고하는 장면은 AS-07 하나뿐이다. 본문에서 제품 가치를 설명하는
자리에는 이 한 장을 쓰는 게 맞다.

**AS-08 / "멈춤 안내 문구는 보이게" / 일부만 충족.**
- 쿠팡 결제 화면 자체에는 "멈춤 안내 문구"가 존재하지 않는다. 그 문구는
  에이전트가 사이드패널에 출력하는 것이고, 위와 같은 이유로 같은 화면에 못 담는다.
- 대신 **결제하기 버튼이 눌리지 않은 상태 그대로** 보이도록 찍었다.

**AS-02 / "dmg 설치 창" / 촬영 불가, HTML 재현으로 대체(승인받음).**
- 시도한 것: 실제 dmg(337MB)를 내려받아 마운트해서 창 배경·아이콘 배치를
  그대로 쓰려 했으나, `hdiutil attach`가 `장치가 구성되지 않았음`으로 실패했다.
  2회 시도 후 중단했다.
- 결과적으로 실제 Aside 앱 아이콘과 macOS 기본 Applications 폴더 아이콘만
  추출해 HTML로 재구성했다. 창 배경 이미지는 실제 dmg의 것이 아니다.

**AS-05 / 샷 리스트에 정의가 없다.**
- 파일명 범위는 AS-01~AS-09인데 AS-05 항목이 어떤 화면인지 지정되지 않았다.
  누락인지 의도적 결번인지 확인 필요.

## 규격 관련 차이

**뷰포트 1440×900 / 탭마다 실제 크기가 다르다.**
- 일반 웹 탭(aside.com, 쿠팡)은 네이티브로 1440×900이 나온다.
- 확장 페이지 탭(설정·온보딩)은 1160×858로 열린다. 이 환경에서는
  `page.setViewportSize` / `emulateMedia` / `addStyleTag`가 전부 사용 불가라
  `document.documentElement.style.zoom`으로 레이아웃 폭을 1440으로 맞춘 뒤
  캔버스에서 정확히 1440×900으로 리샘플링했다.
- **결과 이미지는 전부 정확히 1440×900**이지만, 확장 페이지 3장은 네이티브
  1440 창을 찍은 게 아니라 1440 레이아웃으로 렌더해 스케일한 것이다.

**라이트 모드 / 설정을 바꾸지 않고 적용했다.**
- 앱이 다크 모드라 설정을 바꿔야 라이트가 되지만, 그건 금지 사항이라
  렌더된 페이지의 `<html class="dark">`를 `light`로만 바꿔 캡처했다.
  저장된 설정값(`settings.json`)은 변경하지 않았다.
